## 空白页的实际证据

此前 `login` 在导航前就输出“已打开”，吞掉所有导航异常为“页面仍在加载”，之后仅等待回车或关闭。主框架跳到 `about:blank` 不触发旧guard；不可用页面也能走到 `session_saved`。

本轮有上限的独立会话诊断复现了以下顺序：

1. `/web/user/` 返回HTTP 200，随后渲染“验证码登录/注册”等登录内容。
2. 网站自身账号请求返回code=7、“当前登录状态已失效”。这只证明该采集会话未通过登录校验；不能代表普通Chrome的状态，也不能单凭此断言空白页由登录失效导致。
3. 约2秒后，主框架URL变为 `about:blank`、正文为0字。旧guard仍返回null。
4. 新guard返回 `blank_page` 并关闭受控页。

协议日志中本进程发送的导航命令只有 `Page.navigate` 到BOSS登录地址；随后有关闭命令，没有本进程发送的导航到 `about:blank`。诊断观察到的两个 `initialFrameNavigation` 空白请求属于子框架，不能拿来归因主框架的跳转。

后续定位到主框架跳转前的网站调用栈 `onDevToolOpen → seact`，随后出现“Scripts may close only the windows that were opened by them.”及 `historyDifferentDocument` 到 `about:blank`。对当时官方 [sign vendor 脚本](https://static.zhipin.com/zhipin-sign/v5325/static/js/vendors.19127d44.js) 只做字符串静态解码，确认 `onDevToolOpen` 会调用包含 `window.close()`、`history.back()` 及清空正文的处理函数。这与主框架日志相符，解释了本次登录页空白的直接来源。Playwright 调试连接是与普通浏览器相比的相关触发因素；并未据此认定所有 code=37 或其他会话问题都只有这一原因。

修复将 BOSS 的登录阶段改为无调试连接的原生 Chrome。网站检测代码保持原样；没有修改校验结果、覆盖浏览器 API 或增加隐藏自动化的参数。扫描仍使用 Playwright，是否能获取完整JD须单独验收。

诊断原始文件仅在git忽略的私有 `data/china/diagnostics/`，不纳入仓库。协议日志可能含会话数据，不应分享原文。

## 已修正的问题

| 环节 | 原问题 | 现在的行为 |
|---|---|---|
| BOSS登录启动 | Playwright调试连接触发网站关闭/后退处理 | 启动普通专用Chrome，不附加调试连接；仅报告进程启动，页面由用户查看 |
| BOSS登录完成 | 回车即可返回session_saved | 关闭自有进程并等待退出，仅返回session_unverified；取消、超时不报告成功 |
| 配置目录归属 | 登录和扫描可能争用或向已有Chrome转交URL | 登录和扫描共享同一目录及互斥锁；已有Chrome占用或进程提前退出时拒绝继续 |
| 登录会话交接 | 原生登录与扫描的密钥链不同，扫描读不到Cookie | BOSS扫描采用系统凭据存储，与原生登录一致；有合成Cookie跨进程回归及真实账号code=0证据 |
| 受控登录 | 空白、加载壳及导航异常被忽略 | 猎聘受控登录仍检查可读稳定内容；完成时检查当前页，缺认证依据则session_unverified |
| 导航保护 | 只防验证路径/快速循环，漏主框架空白 | 已访问平台后主框架进入about:blank立即停止；正常空白子框架不误杀 |
| 导航异常 | goto异常时丢弃已提交目标页的有效DOM | 仅在目标URL和新文档timeOrigin均确认后继续有限等待；旧页面或replaceState不算新文档 |
| 薪资字体 | 原文含私有区字符，无法直接读出数字 | 被动核验当前文档已加载字体的URL和SHA-256，已确认版本另存可读薪资；未知版本仍保留原文 |
| 页面归属 | 持久化浏览器默认空白页之外再建采集页 | 自有浏览器复用其初始页，避免留下额外不受保护的空白标签 |
| BOSS详情 | 独立打开裸链接；旧JD可能被错配 | 列表内选卡，校验active卡片ID、面板链接ID、标题、加载状态和完整内容门槛 |
| 关闭岗位 | 关闭卡片不更新面板，原逻辑超时中断 | 读取目标卡片is-close，记录关闭并继续批次 |
| 最后一张卡片 | 消费卡片和pageDone分两次保存 | 同一个检查点保存；同页签名及seen完整匹配时可恢复历史中断状态 |
| 旧记录补录 | 旧观察覆盖当前正文、状态和时间 | 旧记录保留为历史，当前字段按observedAt更新，已关闭岗位不会被旧JD重新开放 |
| 本次采集状态 | 把历史lastAttempt当本次结果 | 使用本次新增observation；本次challenge/login仍保留pending并停止 |
| 辅助导入 | 与DOM判定分离，漏过期/验证提示 | 共用状态判定，整批验证后再写入；保留本次导入版本和来源 |
